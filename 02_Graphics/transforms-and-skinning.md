动画资源保存的是骨骼随时间变化的局部变换；动画系统采样、混合这些变换，再沿骨骼层级求出当前姿势；蒙皮阶段把姿势作用到网格顶点。理解这条链，才能分清“变换如何存储”“姿势如何插值”和“顶点如何变形”。

## 2.1.1 从 TRS 数据到变换矩阵

引擎通常把变换拆成平移 Translation、旋转 Rotation 和缩放 Scale。UE 的 `FTransform` 可用下面的逻辑结构理解，实际布局以引擎版本为准：

```cpp
// 结构示意，不是可直接编译的引擎定义。
FTransform
{
    FQuat   Rotation;
    FVector Translation;
    FVector Scale3D;
}
```

这样便于分别插值，旋转可用四元数参与动画混合，也便于压缩关键帧。与完整 4×4 矩阵相比，这种表示通常需要更少的数值；它也有边界：普通 TRS 不能完整表示任意剪切变换，非均匀缩放与旋转组合时要留意这个限制。

从动画序列看，一根骨骼的一条轨道逻辑上包含平移、旋转、缩放三类 key。采样得到局部 TRS 后，沿父子关系组合成组件空间姿势。进入蒙皮时，再形成骨骼蒙皮矩阵或引擎使用的等价数据，供 GPU 顶点处理使用。

### 2.1.1.1 用一个点确认 TRS 顺序

先使用第一章的 `Vec3`、`Quat` 和 `Rotate`，取点 `(1,0,0)`，缩放为 2，绕 Z 转 90°，最后平移 `(5,0,0)`：

```cpp
// 完整类型与断言见 examples/course/math-labs.cpp。
Vec3 point{1, 0, 0};
Vec3 scaled = point * 2.0;                // (2,0,0)
Vec3 rotated = Rotate(z90, scaled);       // (0,2,0)
Vec3 world = rotated + Vec3{5, 0, 0};     // (5,2,0)
```

每行只做一种操作。若把平移放在旋转前，就会把 `(7,0,0)` 旋转成 `(0,7,0)`，结果不同。这是“矩阵乘法不可随意交换”的可观察后果，不只是公式记忆。

这里用统一缩放以隔离顺序问题。非均匀缩放与不同轴旋转组合，还可能产生单个 TRS 无法完整保存的剪切；不能根据这一个例子推出所有变换都能无损合并为 FTransform。

## 2.1.2 插值为什么要区分三种分量

平移与缩放通常分别线性插值。直接逐元素线性插值两个旋转矩阵，结果一般不再是正交旋转矩阵，可能引入缩放或剪切；因此动画姿势混合通常先分别处理 TRS，再组成需要的变换。

### 2.1.2.1 欧拉角：表达直观，插值需要处理边界

欧拉角用三个角度，按约定顺序绕三根轴旋转。角度可以是任意实数，但存储或显示时常归一到 `[-180°, 180°]`。例如从 `-179°` 转到 `179°`，最短转动只有 2°；直接把两个数平均却得到 0°，走了错误的路径。

- 外旋使用固定参考坐标轴。
- 内旋使用随物体变化的局部坐标轴。

两种约定可以相互换算，但旋转顺序也要对应调整，不能只换名字。以下例子采用列向量和所列矩阵顺序：

```text
Yaw   // 绕 Z
Pitch // 绕 Y
Roll  // 绕 X
R = Rz(Yaw) * Ry(Pitch) * Rx(Roll)

当 Pitch = 90° 时，Yaw 与 Roll 的旋转效果发生耦合。
两者不再独立，可能同时改变两个角度却得到相同姿态。
```

这就是万向节锁：奇异的是欧拉角参数化，物体本身并没有失去三维转动能力。

### 2.1.2.2 四元数：用单位长度约束表示旋转

四元数的目的不是让姿态更容易凭直觉阅读，而是让旋转组合和插值更稳定。可先类比二维复数旋转：

```text
z = x + yi
r = cosθ + i sinθ
z' = r * z
```

三维四元数写成：

```text
q = w + xi + yj + zk
ij = k,  jk = i,  ki = j
ji = -k, kj = -i, ik = -j
```

旋转通常使用单位四元数，将向量视为实部为零的四元数后计算 `v' = q * v * q⁻¹`。对单位四元数，逆等于共轭。若实现用共轭代替逆，却传入未归一化的四元数，就可能带入缩放；不能把“任意非单位四元数在精确求逆时也一定缩放”当成通用结论。

绕单位轴 `n` 旋转 `θ` 的四元数使用半角。例如绕 Z 轴旋转 90°：

```text
axis = (0, 0, 1)
θ = 90°
q.w = cos45°
q.x = 0
q.y = 0
q.z = sin45°
```

将这个四元数代入夹乘并展开，会得到 Rodrigues 旋转公式：

```text
v' = v cosθ + (n × v) sinθ + n(n · v)(1 - cosθ)
```

半角来自四元数表示与这次夹乘的代数关系，不能把左右两次乘法简单理解成两个独立的半角旋转。

### 2.1.2.3 Slerp 与最短路径

单位四元数位于四维单位球面。Slerp 沿球面弧插值，适合需要匀角速度的两姿态过渡；实际动画混合也可能采用归一化线性插值等方式。

`q` 与 `-q` 表示同一三维旋转。为了选择短弧，先把两端放到同一半球：

```cpp
if (dot(q0, q1) < 0)
{
    q1 = -q1;
}

result = Slerp(q0, q1, t);
```

四元数避免了欧拉角参数化的万向节锁，但仍需正确处理归一化、符号和插值约定。

## 2.1.3 从骨骼姿势到线性蒙皮

绑定姿态是网格与骨骼建立蒙皮关系时的姿势。每根骨骼有相对父骨骼的绑定变换，沿层级组合后，得到模型空间或组件空间的绑定矩阵 `B_i`。

逆绑定矩阵 `B_i⁻¹` 先把绑定姿态下的模型顶点转换到第 i 根骨骼的空间。再乘当前姿态的骨骼矩阵 `C_i`，便得到这根骨骼应该怎样带动顶点。采用列向量时：

```text
M_i = C_i * inverse(B_i)
p' = Σ weight_i * (M_i * p)
Σ weight_i = 1
```

这里的矩阵必须在同一空间约定下计算；若引擎采用行向量，乘法顺序相应改变。CPU 负责采样、混合和骨骼层级计算，GPU 通常按顶点权重完成最后这一步。

### 2.1.3.1 先用一维骨骼平移推演逆绑定

把旋转和缩放暂时设为单位变换，只看 X 轴。绑定时骨骼在 10，顶点在 11；当前骨骼移到 12：

```cpp
double bindBone = 10.0;
double currentBone = 12.0;
double vertex = 11.0;
double boneLocal = vertex - bindBone;       // 1：逆绑定
double movedVertex = boneLocal + currentBone; // 13：当前骨骼变换
double blended = 0.25 * movedVertex + 0.75 * vertex; // 11.5
```

第一根骨骼权重为 0.25，另一根保持绑定姿态的骨骼权重为 0.75，所以最终位置是 11.5。若忘记逆绑定而直接 `11+12`，会得到 23，把绑定时已经存在的偏移又计算一次。

完整三维情形把减法与加法换成相应矩阵运算，但逻辑顺序相同：先回到绑定骨骼空间，再由当前骨骼带回公共空间，最后按权重混合。[数学实验](../examples/course/math-labs.cpp)对 TRS、旋转和这个结果作了数值断言。

### 2.1.3.2 糖果纸效应与改进办法

线性混合蒙皮把多个骨骼变换后的顶点位置做加权平均。两个差异较大的旋转混合时，关节附近可能收缩，前臂扭转时尤其像拧紧的糖纸。

原笔记中的几种处理方向各自解决不同部分：

1. 加 Twist Bone，将手腕的旋转分摊给多根骨骼，减小相邻骨骼的旋转差。
2. 调整权重过渡，避免一圈顶点突然以 50/50 混合差异很大的旋转；这能缓解问题，但不改变线性蒙皮本身的缺陷。
3. 添加姿态修正形态，例如前臂转到 90° 时补偿塌陷。
4. 使用双四元数蒙皮。双四元数可表示刚体旋转和平移，对其加权并归一化后进行蒙皮，通常能更好保持体积。

```text
Q = qr + ε qd
qr = real part，实部四元数
qd = dual part，双部四元数
```

双四元数并非没有代价：非均匀缩放需要额外处理，弯曲处可能鼓包，工具链和引擎也必须支持。实际项目要结合资源、骨架和变形要求选择。

## 2.1.4 学习检查：画出每个值所在的空间

为 `p`、`B_i`、`C_i`、`M_i` 标注输入与输出空间；把绑定和当前姿态设为相同，顶点应当保持原位。再让两个影响骨骼都施加同一平移，权重和为 1 时顶点应只平移一次。如果结果不满足这两条，先检查空间、矩阵顺序和权重，再怀疑动画资源。
