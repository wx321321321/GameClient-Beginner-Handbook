先读 [4.4 伤害、属性与技能](shooter-combat-and-abilities.md)。Arena 为教学明确了属性公式，本篇保留原项目的五字段接口，但没有该项目求值源码，因此不把新教程的公式补写成原工程事实。

这篇记录两层问题：原项目怎样组织和修改战斗属性，以及属性变化怎样通过网络到达客户端。先把属性计算和网络传输拆开，才能知道一个数值不对时应查计算器、同步字段还是表现回调。

## 4.13.1 combat_attr：战斗单位的属性入口

原项目把 `combat_attr` 挂在每个战斗单位（原文 `conbatunit`，具体类名待源码核对）下。以 `combat_avatar` 为例，内部又分成三组：

```text
combat_avatar.combat_attr.avatar_attr
combat_avatar.combat_attr.gun_attrs
combat_avatar.combat_attr.equip_attrs
```

它们分别承担角色、枪械和装备相关属性的管理。这里是原项目的职责划分，不是 UE 或其他引擎的通用 API。

每个原子属性由 `IModAttr` 一类的数据承载，原笔记记录了五个字段：

| 字段 | 原笔记含义 |
| --- | --- |
| `name` | 原子属性名称 |
| `ori_value` | 初始值 |
| `pct_change` | 百分比变化 |
| `value_change` | 固定值变化 |
| `cov_value` | 覆盖值 |

原稿没有给出最终求值函数，所以这里不补造“先加固定值再乘百分比”之类公式。百分比之间如何叠加、覆盖值优先级、覆盖是否允许为零，都要以 `IModAttr` 的实际实现为准。

## 4.13.2 一次属性修改经过哪些层

修改入口使用一个代号或 ID，代号同时映射到操作对象与操作方式。它不只是“属性名字的数字写法”，还决定这次修改是百分比、固定值还是覆盖等操作。

```text
修改代号 / ID + 数值
→ 查询对应属性名与操作方式
→ 找到 avatar_attr / gun_attrs / equip_attrs 中的目标
→ 将改动写入相应 modifier
→ 按属性求值规则获得结果
→ 需要同步的 attr 变化进入网络同步链
```

`combat_attr` 在服务端和客户端都存在，但它们是不同进程里的对象。原项目同步的是注册的 `attr` 数据，不能据此认为整个属性管理器的内部状态都会自动复制。

客户端收到变化后，更新本地属性镜像，触发 `on_setattr` 等回调，再重新计算相关结果并刷新表现。究竟同步 modifier 的组成数据还是最终值，需要看具体字段声明；这会直接决定客户端应重算什么。

## 4.13.3 帧同步、状态同步和属性同步的关系

```text
多人游戏同步
├─ 帧同步：按逻辑帧分发输入，由各端重算结果
├─ 状态同步：发送权威端计算后的状态
│  ├─ 状态快照
│  └─ 属性变化同步
└─ RPC / 事件消息：传递操作请求或事件，可与上述方案配合
```

RPC 描述调用或消息机制，不能只凭使用 RPC 就判断游戏采用哪一种同步模型。混合方案也不固定是“战斗帧同步、外围属性同步”，只是原笔记中一种可能组合。

### 4.13.3.1 帧同步：各端对同一帧输入得到同一结果

这里的帧通常是逻辑帧或 Tick，不是显示器画面帧。

```text
客户端发送操作
→ 服务器收集、排序
→ 广播同一逻辑帧的输入集合
→ 各客户端执行相同逻辑
→ 得到一致结果
```

要达到这个目标，必须约束初始状态、输入顺序、逻辑帧推进、随机数序列与计算确定性。相同随机种子还不够，随机数调用次数和顺序也要一致；浮点差异、无序容器遍历等都可能破坏一致性。

### 4.13.3.2 状态同步：权威端决定结果

```text
客户端发送操作意图
→ 服务器验证并运行游戏逻辑
→ 得到权威状态
→ 将结果发给相关客户端
→ 客户端更新本地状态与表现
```

客户端可以预测或平滑表现，但最终结果的裁定权取决于具体系统。在本文的属性场景中，应分清本地预览值与服务端确认后的值。

### 4.13.3.3 属性同步：以对象字段为单位传递状态

```text
属性发生变化
→ 设置脏标记，或由同步系统检测变化
→ 收集符合范围和条件的字段
→ 发给相关客户端
→ 客户端更新字段
→ 触发配置的回调并刷新表现
```

![同步方式原笔记示意图](assets/image-7.png)

属性计算解决“值怎么来”，属性同步解决“把哪些值发给谁”，回调解决“收到之后更新什么”。原项目的 `PropertyMetaClass`、`asiocore`、同步标记和 AOI 接收范围，见[网络同步链路](network-synchronization.md)。
