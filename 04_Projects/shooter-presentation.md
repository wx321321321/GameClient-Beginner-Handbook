Arena 的表现层消费运动快照、武器状态和射击事件，生成姿势、相机、声音与特效。
表现层可以预测，也可以平滑，但不能自行决定命中、扣弹或复活。
因此先实现可调试的胶囊与射线，再接动画资源；资源缺失时玩法规则仍应能够测试。

## 4.6.1 从只读表现快照到最终姿势

动画输入是一份明确的只读数据：局部速度、接地状态、瞄准角、姿态、装备类型、武器阶段、生命版本。
每帧从角色状态生成快照，再交给动画更新；不要让动画图在任意线程随意读取可变游戏对象。
“读取哪些变量”同时决定线程安全、网络复制和调试可见性。

| 信息 | 来源 | 表现用途 |
| --- | --- | --- |
| 平面速度和方向 | 已预测/已插值的运动状态 | 站立、行走、跑步混合 |
| 接地、垂直速度 | 运动模块 | 起跳、空中、落地 |
| 瞄准相对身体角度 | 视角与身体朝向差 | Aim Offset 或瞄准姿势 |
| Reloading 与结束时间 | 权威状态或受控预测 | 换弹层、进度对齐 |
| ShotAccepted/PredictedShot | 事件路由 | 枪口、枪声、后座 |
| Dead、lifeId | 战斗状态 | 死亡姿势、停止旧动作 |

最初只做 Idle/Move/Air/Dead 的基础运动状态。
每个转换条件写成可观测的规则，速度阈值加迟滞，避免角色在静止边缘反复切换。
起跳事件和“当前不接地”不是同一件事：走下台阶不应总播放主动起跳。
落地依据运动状态迁移，落地强度依据落地前速度；不要每帧检测地面命中就重播落地。

## 4.6.2 上半身动作叠在运动之上

基础全身姿势先解决下肢运动，然后按骨骼遮罩叠上持枪、瞄准、射击和换弹。
遮罩的脊柱起点、肩部权重和手臂覆盖范围取决于骨架，不能把某个项目骨骼名直接当通用约定。
左手握枪 IK 最后对齐枪上握持点，右手通常由持枪姿势或武器挂点关系约束。
换弹期间左手需要离开握持点，应由曲线或状态降低约束权重，否则会出现手被“拉回枪上”。

```text
基础 Locomotion
  -> 上半身持枪/换弹分层
  -> 瞄准偏移与添加式后座
  -> 手部 IK、脚部 IK 等末端修正
  -> 最终骨骼姿势
```

这是 Arena 的起始顺序，具体图顺序需用实际资源验证；不同约束互相覆盖时应明确谁最后写入。
添加式动画依赖正确参考姿势；把普通动画直接当 Additive 会产生错误偏移。
UE 可使用 Layered Blend per Bone 的 Branch Filter 或 Blend Mask 实现分层。
[Epic 动画混合节点](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-blueprint-blend-nodes-in-unreal-engine)
原有 [动画概览](../03_UE/animation-overview.md) 与 [ALS 实践](als-locomotion.md) 可用于对照资源、曲线和图的职责。

动画通知适合发出脚步声、弹壳、装饰性的换弹音等时间点。
不能让未播放、被打断或被裁剪的动画通知成为服务器补弹或技能完成的唯一入口。
换弹完成 tick 属于武器规则，动画需要向这个结果靠拢，而非反向拥有弹药。

## 4.6.3 Root Motion 选择移动权，而不是简单开关

Arena 普通移动第一版由运动模块驱动胶囊，动画按速度播放原地运动。
这使输入、碰撞和网络预测更容易先形成稳定闭环。
翻越、处决等动作若采用 Root Motion，要定义它如何进入运动模式、如何受碰撞约束、如何被中断和同步。
根骨骼位移、角色胶囊位移、模型的视觉校正偏移是不同数据，不能叠加两次。

UE 的 Root Motion 会提取动画中的根运动，并由移动组件应用；应用方式受 Root Motion Mode 与运动状态影响。
不要由此推断所有动画资源都会自动推着角色走。[Epic Root Motion](https://dev.epicgames.com/documentation/en-us/unreal-engine/root-motion-in-unreal-engine)
本课程不要求第一版自行实现网络 Root Motion；使用引擎已有路径时按目标引擎版本核对同步约束。
Motion Warping、Distance Matching、Pose Warping 是不同问题的工具，先指出需要修正的位移、相位或姿势，再选择。

## 4.6.4 Foot IK 的输入是地面约束

每只脚在合理探测范围内查询地面点与法线，转换到 IK 求解所需的空间。
脚目标做平滑并限制最大偏移，骨盆按双脚可达性适度下调，避免伸腿超过长度。
支撑脚可在接触阶段锁定世界目标；抬脚阶段逐渐释放，不能所有时间都钉在原地。
台阶边缘、空中、快速旋转、传送和网络大校正需要降低或重置 IK 权重。
移动平台上的锁定目标应相对平台保存，并使用有效平台句柄；否则平台移动时脚会留在旧的世界位置。
Foot IK 改视觉姿势，不能把脚探测结果直接当角色权威接地与台阶攀爬规则。
同一个角色不需要在游戏逻辑、动画图、特效模块分别做三套相同地面查询。

## 4.6.5 相机先确定控制量，再添加效果

基础相机由输入视角、目标位置、碰撞避障和模式产生。
ADS 改变 FOV、相机偏移、枪械姿态与灵敏度策略，应该使用同一模式权重平滑切换。
FOV 用水平还是垂直角需和引擎接口一致；这里内部角度用弧度，调用使用角度的引擎 API 时只转换一次。
第三人称相机与枪口的两段查询参见 [武器与弹道](shooter-weapons-and-ballistics.md)。

把后座拆成三个可独立调节的量：

- 瞄准后座：改变后续视角或瞄准意图，影响弹道。
- 相机视觉后座：短暂震动与回弹，是否影响实际瞄准必须显式约定。
- 枪模后座：局部位移与旋转，只影响看到的武器。

散布是服务器计算的随机方向偏移，与上述后座不等价。
准星扩张应反映当前散布配置或状态，不能只根据枪模晃动随便放大。
相机滚转、强烈震动等提供设置项，并保证降低效果不改变权威射线精度。

下面是 C++17 独立的指数收敛函数，可编译为目标文件。
它适合 ADS 权重与简单视觉偏移，半衰期使用秒。

```cpp
#include <cmath>
#include <stdexcept>
double Approach(double value, double target, double dt, double halfLife) {
    if (!std::isfinite(value) || !std::isfinite(target) ||
        !std::isfinite(dt) || !std::isfinite(halfLife) ||
        dt < 0 || halfLife <= 0)
        throw std::invalid_argument("invalid smoothing parameters");
    const double remain = std::exp2(-dt / halfLife);
    return target + (value - target) * remain;
}
```

目标不变时，经过一个半衰期，误差减半；按不同帧率分步得到相近结果。
它不像固定 `Lerp(value,target,0.1)` 那样直接把收敛速度绑在帧数上。
这是一阶视觉平滑，没有弹簧速度与振荡；需要真实弹簧响应时应另存速度并选稳定积分方案。
传送、切镜和复活可直接重置，不必为了“平滑”从旧相机穿越整张地图。

## 4.6.6 音效和特效池要有生命周期

ShotAccepted 包含射击键、发射位置方向、武器表现配置和服务器时间。
远端根据该事件播放枪声、火焰和曳光；命中事件另提供表面材质、位置、法线与结果。
一发接受事件不意味着一定有命中事件，打空仍要有开火反馈。

池化对象借出时设置位置、颜色、发射器参数、音量和寿命，归还时清除上一用途的绑定与状态。
对象池省去频繁创建销毁，但不等于所有效果都应该无限保留。
设置总容量、每种效果上限和降级优先级，例如远处弹壳可丢，近处关键命中反馈优先。
音频并发也要限额，不能允许一百个远处枪声淹没本地受击提示。
弹孔附着在运动物体上时保存目标句柄与局部变换，目标销毁或离开可见集时妥善回收。

异步加载回调带请求版本和目标句柄；资源终于到达时，目标可能已死亡、换枪或被卸载。
旧请求结果应被忽略并释放，不应把旧枪模型重新挂到新装备上。
对象池租约也可以带 generation，避免迟到的停止回调关闭刚被复用的新效果。

## 4.6.7 预测事件使用同一个射击键收尾

本地按下开火时可以立即播放枪口与短枪声，并记录 `Predicted` 事件。
该事件以 `sessionEpoch + shooterHandle + ShotSeq` 查找，不依赖“最近一次开火”的可变全局字段。
服务器接受时把它标为 Confirmed，校正需要校正的方向、弹药和轨迹，不能再播放一次同样枪声。
服务器拒绝时标为 Rejected，取消后续曳光、弹孔和未完成动画，恢复预测弹药并平滑衰减视觉后座。

```text
不存在 --本地预测--> Predicted --服务端接受--> Confirmed
                         |
                         +--服务端拒绝--> Rejected
不存在 --远端接受事件--> 直接播放一次 Confirmed 表现
```

这是需要引擎资源与事件路由的逻辑示意。
已经听见的枪声不能撤回，所以预测反馈要选择可接受的短反馈，不提前播放永久击杀确认。
命中标记可区分预测与确认；竞技规则下击杀、奖励和重要受击判断以服务器结果为准。
预测重放只计算状态，不再次创建 Predicted 表现；超时未确认事件在有限时间后清理并提示连接状态。
重连新 epoch、复活新 lifeId、实体 generation 变化时清除对应旧事件。

## 4.6.8 最小可验收的表现集

| 测试 | 通过条件 |
| --- | --- |
| 站立、移动、跳跃时开火换弹 | 下肢连续，上半身动作可辨，无锁手拉扯 |
| 30/60/144 FPS 切 ADS | 相同半衰期，最终视角与模式一致 |
| 本地预测被拒绝 | 一次短反馈、没有确认击杀、状态恢复 |
| 同一结果重复到达 | 不重复枪声、弹孔和震动 |
| 武器资源加载晚于切枪 | 旧资源不覆盖新装备 |
| 多人持续开火 | 池、音频并发和内存达到稳定上限 |
| 跨台阶与移动平台 | 脚部修正受限，权威胶囊不被 IK 偷改 |

练习：关闭所有动画和粒子，只保留调试胶囊、准星与状态文本。若战斗结果因此改变，就追查表现层在哪里越权写了规则状态。
