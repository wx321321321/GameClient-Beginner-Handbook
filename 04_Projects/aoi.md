先读 [4.5 联机与服务器权威](shooter-network-authority.md)的兴趣范围，再用本篇理解原项目网格、滞回和观察关系。下面的 35/41 与 100 ms 都是原记录参数，不是 Arena 的默认配置。

AOI（Area of Interest）决定一个观察者需要接收哪些实体的信息。它首先是网络相关性管理；实体进入 AOI 后，还可能受到客户端视锥、遮挡、隐身等规则影响，因此 AOI 内不等于画面上必然可见。

以下周期、网格尺度、距离阈值和字段名来自原项目笔记，不是所有引擎的统一配置；仓库没有对应服务端源码，实际单位及配置入口需回到原项目核对。

## 4.15.1 位置更新与 AOI 刷新分开执行

原项目创建 `space` 时设置刷新定时器，记录的周期是 **100 ms**。角色移动后先更新位置及所属空间网格，不立即遍历所有角色计算进入、离开。

```text
客户端移动请求 / 服务端物理推动
→ 更新实体位置
→ 更新实体所属网格
→ 等待 space 的 AOI 定时刷新
→ 查询候选实体
→ 精确判断距离
→ 与上一轮关系比较，产生进入/离开事件
```

原文“100/100 分成网络单元”在这里整理为**空间网格**：网格用于缩小候选集合，不是网络通信连接。`100/100` 究竟表示单元边长还是划分数量，原稿没有说明，保留为配置待核对项。

刷新时，对每个观察者根据最大可见距离算出覆盖网格，只对这些网格内的候选实体做精确距离测试。这样避免了全地图两两比较。

## 4.15.2 用稳定性跳过不必要的重算

原项目将实体区分为 `active` 与 `stable`。稳定实体还要检查附近网格是否发生影响视野的变化；实体自己没动，不代表周围没有人走进来。

只有自身及相关网格都满足稳定条件，才可跳过重新计算。这里需要关注的是“哪些变化会让网格或实体变脏”，而不只是位置是否相同。

## 4.15.3 用滞回区间减少边界抖动

原笔记记录的距离规则是：

```text
距离 < 35：进入
35 ≤ 距离 < 41：保持上一轮状态
距离 ≥ 41：离开
```

因此，原来不可见的对象走到距离 38 时仍不进入；已经可见的对象退到距离 38 时仍不离开。进入阈值和离开阈值不同，能够避免人在边界附近轻微移动就不断创建、销毁客户端实体。

### 4.15.3.1 用 C++ 跟踪滞回状态

```cpp
bool UpdateInterest(bool wasVisible, float distance) {
    return wasVisible ? distance < 41.0f : distance < 35.0f;
}
// 初始 false，依次输入 38、34、38、41，结果 false、true、true、false。
```

前提是距离有限且非负，两个阈值使用同一单位。注意每一步都将上一步结果传回 `wasVisible`；如果每次都传 `false`，就丢失了“保持”的记忆。真实系统还需要实体有效性、权限、初始快照和离开消息，距离函数只负责其中一个判定。

## 4.15.4 正向关注表与反向观察者表

若 **A 能看见 B**，记录应为：

```text
A.m_interest[B]       // A 正在关注 B
B.m_interested[A]     // B 被 A 关注
```

- `A.m_interest` 用于回答“A 当前需要哪些实体”。
- `B.m_interested` 用于回答“B 发生变化时，应通知哪些观察者”。

原稿写成“A 进入 B 的视野”却使用上面的字段，主客体反了；若真是 B 看见 A，应写 `B.m_interest[A]` 与 `A.m_interested[B]`。两张表维护的是同一条有向关系，不意味着 A、B 必然互相可见。
