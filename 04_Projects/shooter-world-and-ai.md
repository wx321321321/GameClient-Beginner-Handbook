Arena 的第一张地图只需要一块可行走地面、几面掩体、一段坡道、一个拾取物和两个出生点。
先让碰撞与规则可验证，再替换成正式美术。
本篇把“世界中存在什么”“角色能到哪里”“AI 决定做什么”分开，避免用一个巨大的关卡脚本管理所有行为。

## 4.7.1 关卡数据要服务不同查询

可见网格、移动碰撞、射击碰撞、交互体积和导航数据可以来自同一物体，但用途不同。
一片装饰树叶可以可见却不挡子弹；一扇门既阻挡移动，也可能影响视线与导航。
这些规则应由碰撞层和查询过滤定义，不能在命中回调里临时比较物体名字。

| 查询 | 输入 | 输出 | 主要消费者 |
| --- | --- | --- | --- |
| 角色扫掠 | 胶囊、起点、位移、过滤层 | 最早碰撞、法线、可移动距离 | 运动模块 |
| 武器查询 | 起点、方向、射程、时间策略 | 命中对象与部位 | 战斗模块 |
| 交互查询 | 玩家姿态、范围、目标类型 | 候选交互目标 | 提示 UI 与服务端交互 |
| 视线查询 | 感知起点、目标点、遮挡层 | 是否可见 | AI 感知 |
| 导航查询 | 起终点、代理尺寸、代价过滤 | 路径或失败原因 | AI 路径跟随 |

灰盒关卡先验证米制尺寸：门宽是否容纳胶囊，台阶是否符合最大高度，坡度是否可走。
把引擎厘米转换到米的边界固定下来，不能让一部分配置填 180，另一部分填 1.8 却都叫身高。
射击用的简化碰撞和显示网格偏差过大时，玩家会觉得“明明打中了却没伤害”，需要调试叠加对比。
导航可走不代表运动碰撞一定能通过，二者代理半径、高度和坡度参数要一致。

## 4.7.2 拾取物由服务器完成一次归属转移

客户端根据本地距离与朝向显示“可拾取”，发送交互请求：请求序号、玩家句柄、目标句柄。
服务器重新检查玩家存活、目标存在、距离、视线、容量和归属条件。
接受时把拾取物从 Available 迁移为 Consumed，并把物品或弹药加入玩家状态，一次性提交。
两个玩家同时争抢，由规则线程确定唯一成功者；不能先各自收到成功，再异步删除物品。
结果附带请求 ID，重试只返回原结果，不能再次添加弹药。

```text
Available --验证并提交--> Consumed --到刷新时刻--> Available（新生命周期）
```

是否使用新实体句柄或增加拾取物版本取决于实体系统，但旧请求不能消费刚刷新出的新物品。
刷新表应记录出生位置和资源 ID，不持有已卸载关卡对象的裸指针。
按住交互型动作额外保存开始 tick、距离/视线中断条件和完成 tick。
HUD 的环形进度可以预测，完成归属仍来自服务器结果。

## 4.7.3 导航路径是计划，移动执行还要处理碰撞

第一版可用二维格网学习 A*，接入引擎时采用其导航网格与路径跟随能力。
路径规划输出一串节点或多边形，转成可跟随路径点后，运动模块仍负责加速度、转向和碰撞。
动态避让负责近处其他角色的避碰，不能指望静态路径一经计算就永远没有障碍。
UE 导航网格从碰撞几何生成带代价的多边形图，并提供独立的动态避让机制。
[Epic 导航系统](https://dev.epicgames.com/documentation/en-us/unreal-engine/navigation-system-in-unreal-engine)

A* 维护已知最小路径成本 `g(n)`，以及到终点的估计 `h(n)`，优先扩展 `f(n)=g(n)+h(n)` 最小的节点。
要保证本示例寻找最短路径，启发值不能高估真实剩余成本，并令终点的启发值为零。
四方向、每步成本至少为 1 的格网可用曼哈顿距离；允许廉价对角移动后，原启发值可能高估，应换成匹配的下界。
`h=0` 退化为 Dijkstra，是验证启发函数的一个基线。
非负边权是本课程前提。若永久关闭节点且不允许重开，需保证启发函数一致；否则发现更小 g 时应重新加入。

```text
g[start] = 0；其余为无穷
open 放入 start，优先级为 g[start] + h[start]
循环取最低优先级节点 u：
  丢弃已被更好 g 取代的旧队列项
  若 u 是 goal：沿 parent 回溯路径
  对每条 u -> v：
    candidate = g[u] + edgeCost
    若 candidate < g[v]：更新 g[v]、parent[v]，将 v 放入 open
open 为空：不可达
```

这是算法逻辑示意；实际任务要加最大扩展节点数、时间预算和取消令牌。
优先队列常允许重复入队，再跳过过期项；不要在线性扫描容器中每次找最小节点却不测规模。
路径结果携带请求版本、目标版本和导航数据版本，异步返回时核对是否仍适用。
AI 已换目标、死亡或区域卸载后，旧路径不得覆盖新计划。

## 4.7.4 感知记录证据，不直接等同于全知

视野先做距离和视角粗筛，再对候选目标做视线查询，避免对全地图每个角色每 tick 射线检测。
声音感知输入声源位置、强度、类别与时间，给出可调查线索，而不是自动提供声源的精确持续坐标。
记忆保存目标句柄、最后看到的位置、最后看到的 tick 和可信度。
离开视野后可以去最后位置搜索，不能继续读取真实位置追踪，除非这是刻意的 AI 玩法能力。

感知可用低于模拟的频率更新，并将不同 AI 的更新分摊到不同 tick。
这只降低“做决定”的频率，已决定的移动仍每个模拟 tick 执行。
区分可见、记忆有效、射线可命中和武器射程；看到目标不一定可以开火。

下面是 C++17 可编译为目标文件的纯决策示例。
它读取已验证感知结果，输出动作意图，不直接移动世界对象或扣血。

```cpp
#include <cstdint>
enum class Mode { Patrol, Chase, Search, Attack, Dead };
struct Senses {
    bool alive = true, visible = false, hasMemory = false;
    bool inRange = false, lineOfFire = false;
    std::uint64_t now = 0, lastSeen = 0;
};
struct Intent { Mode mode; bool move; bool fire; };
Intent Decide(const Senses& s) {
    if (!s.alive) return {Mode::Dead, false, false};
    if (s.visible) {
        if (s.inRange && s.lineOfFire)
            return {Mode::Attack, false, true};
        return {Mode::Chase, true, false};
    }
    // 180 tick = 示例 60 Hz 下 3 秒；先比较，防止无符号下溢。
    if (s.hasMemory && s.now >= s.lastSeen && s.now - s.lastSeen <= 180)
        return {Mode::Search, true, false};
    return {Mode::Patrol, true, false};
}
```

这里没有模拟射击能力；`fire=true` 仍要交给同一武器 FSM 检查冷却、弹药和状态。
真实 FSM 还需保存进入时刻、目标、路径与进入/退出动作；这个函数只展示状态选择优先级。
Attack 和 Chase 的射程边缘加入迟滞，防止每 tick 来回切换。
搜索结束后回到巡逻，路径失败后退避重试；不能在同一帧无限重新寻路。

行为树适合把选择、顺序与可中断任务组合成数据结构。
即便采用行为树，也要明确黑板键的写入者、任务取消时资源释放、异步完成回调是否过期。
不要同时维护一套互相竞争的 FSM 状态和一套未同步的行为树状态。
第一版四五个行为用 FSM 足够；行为增多后再根据调试与复用需求迁移。

## 4.7.5 AI 运行在服务器，客户端消费结果

AI 与玩家共用运动、武器和伤害规则，只是动作命令来源不同。
客户端通常不需要复制整棵行为树；复制角色运动、必要动画状态与可见事件即可。
服务器保存目标选择和随机种子，日志记录决策原因，以便重现“为什么隔墙开枪”。
瞄准误差、反应时间、连发长度是明确的难度参数，不靠随机丢服务端 tick 来降低难度。

服务端大量 AI 时先限制每帧感知和寻路预算，再考虑分区调度、缓存和任务系统。
进入预算队列不等于失去物理碰撞与生命结算，暂停高级决策仍需维持必要状态。
低频决策带来的反应延迟应在玩法允许范围内，不应把服务端过载伪装成正常难度。

## 4.7.6 流式加载与 AOI 解决不同问题

流式加载控制本机内存中的关卡和资源，AOI 控制某个连接接收哪些世界状态。
它们可以共用空间分区索引，但不能把客户端卸载一个区块解释为服务器销毁那里的所有敌人。
Arena 小地图先完整加载；地图扩大后再把区域状态划分成 Unloaded、Loading、Ready、Unloading。
玩家即将进入时预取资源、碰撞和导航数据，Ready 后才允许依赖它的玩法激活。

出生、复活、传送需要预热目标区块，或者在等待状态中阻止输入与碰撞穿落。
必须区分“模型资源未显示”和“权威碰撞尚不可用”，不能静默让角色穿过缺失地面。
区块卸载前取消该区任务、释放订阅、清理或迁移可持久实体；在途资源回调用版本检查失效。
服务器保留哪些区块由其模拟需求决定，不直接照搬一个客户端的摄像机位置。
UE World Partition 提供网格单元和流式源机制，传送目标可通过额外流式源预加载。
[Epic World Partition](https://dev.epicgames.com/documentation/en-us/unreal-engine/world-partition-in-unreal-engine)

## 4.7.7 验收地图要故意包含难点

- 两个玩家同 tick 拾取同一物体，恰有一个成功，重发请求不会增加物品。
- 路径穿过窄门时，导航代理尺寸与实际胶囊一致；不可达目的地明确失败。
- 目标消失后 AI 搜索最后位置，超时结束；不会凭客户端隐藏信息持续精确追踪。
- AI 与玩家使用同样武器冷却和伤害规则，关掉动画后攻击结果保持一致。
- 寻路任务完成前销毁 AI，回调不访问失效实体，也不把路径发给重用槽位的新角色。
- 玩家快速跨区和传送，资源加载等待可见，内存最终回落，没有重复刷出的拾取物。

练习：增加一扇可开关门，分别说明它如何影响移动碰撞、射击遮挡、视线、导航和历史命中查询。
如果这五个答案混成了“修改可见性”，就还没有定义完整的世界规则。
