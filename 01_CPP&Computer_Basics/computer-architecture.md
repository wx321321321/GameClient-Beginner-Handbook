## 1.2.1 从冯诺依曼模型认识 CPU

冯诺依曼模型把计算机分成运算器、控制器、存储器、输入设备和输出设备五部分。指令和数据都以二进制形式保存在存储器中。某段字节是被取来当指令执行，还是作为数据读取，取决于访问方式和执行上下文，并不是每个字节自带一个“指令/数据”标签。

一条指令通常包含操作码，以及操作数或寻址方式等字段。操作码说明“做什么”；操作数字段可能直接给出数值，也可能给出寄存器编号或形成内存地址的信息，不能全部理解为内存地址。

CPU 中，控制单元 CU 负责取指、译码和协调执行，算术逻辑单元 ALU 执行整数算术与逻辑运算。现代 CPU 还有多个执行单元、流水线和乱序执行部件；教材的 CU/ALU 模型是在提取它们的基本职责。

先把这个过程接到一行游戏代码上：

```cpp
int hp = 100;
int damage = 7;
hp -= damage;       // 这一刻之后，C++ 语义上的 hp 是 93。
```

如果这次减法确实在运行时执行，机器要取得两个操作数，让整数执行单元做减法，再保存结果；控制部分协调这些步骤。但不能反过来要求它必须“读两次 RAM、算一次、写一次 RAM”：操作数可能已在寄存器中，写回也可能只改寄存器。上面三个值全部已知时，优化器甚至可能直接使用常量 93。先理解程序要求的结果，再讨论某个编译结果怎样实现它，才不会把 C++ 一行代码误认为固定的一条机器指令。

### 1.2.1.1 寄存器各自保存什么

寄存器位于 CPU 内部，保存正在使用的数据、地址和执行状态。

| 名称 | 作用与边界 |
| --- | --- |
| 通用寄存器 GPR | 保存操作数、地址或中间结果。教材中的 ACC（累加）、MQ（乘商）、X（操作数）、IX（变址）、BR（基址）体现不同用途，并非每种现代 CPU 都按这些名字设置独立寄存器 |
| MAR，主存地址寄存器 | 教材数据通路中保存本次访存地址的部件，宽度取决于该模型的地址位数 |
| MDR，主存数据寄存器 | 暂存本次从存储器读出或准备写入的数据，宽度由具体数据通路决定 |
| IR，指令寄存器 | 暂存当前指令。变长指令处理器的实际取指、译码结构比单个固定宽度 IR 更复杂 |
| PC，程序计数器 | 标识指令流的位置。顺序执行时前进，分支、调用和返回会改变它；具体指向当前还是下一条指令由体系结构和讨论阶段决定 |
| PSW/状态寄存器 | 保存条件标志和部分控制状态，例如零标志、进位标志、中断相关状态 |

MAR、MDR 等常用于解释 CPU 内部工作，不一定是程序员能直接访问的体系结构寄存器。

### 1.2.1.2 字长、地址位数与性能指标

“多少位的机器”不是说所有部件都具有相同宽度。

- **机器字长**：教材中通常指整数运算的基本宽度，与通用寄存器和整数数据通路有关；不排除另外存在更宽的 SIMD 运算。
- **存储字长**：某个存储组织一次读写的数据位数。现代内存的总线宽度、突发传输长度和 CPU 的访存操作大小不能简单画等号。
- **指令字长**：一条指令的编码长度，由指令集决定，可以固定，也可以变化，与机器字长不必相等。
- **寻址空间**：取决于有效地址位数和编址单位。若按字节编址，n 位地址理论上可区分 `2^n` 个字节；虚拟地址、物理地址的有效位数可能不同，实际支持范围还受 CPU 和操作系统限制。

时钟周期 T 是一个时钟周期的时长，主频 `f = 1 / T`。CPI 是一段程序平均每条指令消耗的周期数。比较性能要一起看指令数、CPI 和主频：

```text
CPU 执行时间 = 指令数 × 平均 CPI × 时钟周期
            = 指令数 × 平均 CPI / 主频
```

主频高不等于任意程序都更快；指令数、并行执行能力、分支预测和 Cache 缺失都会改变结果。

## 1.2.2 数据在机器里怎样表示

### 1.2.2.1 进制、字节编址与大小端

C++ 整数字面量可用 `0b` 表示二进制、前导 `0` 表示八进制、`0x` 表示十六进制；`0o` 是某些其他语言的写法，不是标准 C++ 的八进制前缀。

常见通用处理器按字节编址，每个地址定位一个字节。一个多字节对象用起始地址标识，占据后续多个字节。常见平台上 `int`/`float` 为 4 字节、`double` 为 8 字节，但这些具体大小不能全部当成 C++ 的跨平台保证。

大小端讨论的是多字节数值在连续地址中的**字节顺序**。以 `0x12345678` 为例：

```text
从低地址到高地址：
大端：12 34 56 78   高有效字节在前
小端：78 56 34 12   低有效字节在前
```

这不改变一个字节内的位权，也不改变数值本身。

### 1.2.2.2 实验：看见的是数值，还是表示这个数值的字节

下面把对象表示复制到字节数组中观察。`memcpy` 在这里复制已有整数的字节，不做数值换算；暂时把 `&value` 理解成“这个对象的位置”，指针章会继续解释地址。

```cpp
#include <array>
#include <climits>
#include <cstdint>
#include <cstring>
#include <iomanip>
#include <iostream>

void inspect_bytes() {
    static_assert(CHAR_BIT == 8 && sizeof(std::uint32_t) == 4);
    std::uint32_t value = 0x12345678;
    std::array<unsigned char, sizeof(value)> bytes{};
    std::memcpy(bytes.data(), &value, sizeof(value));
    for (unsigned char byte : bytes) {
        std::cout << std::hex << std::setw(2) << std::setfill('0')
                  << static_cast<unsigned>(byte) << ' ';
    }
    std::cout << std::dec << '\n';
}
```

在常见小端平台，输出 `78 56 34 12`；大端平台则是 `12 34 56 78`。代码没有要求机器一定采用哪一种，前提是实现提供 `uint32_t` 且满足上面的字节大小检查。转换成 `unsigned` 是为了打印数字，而不是把 `unsigned char` 当字符显示。

再把这些字节原样复制回同类型对象，数值仍是 `0x12345678`。但把“本机对象的字节”直接当网络包或文件格式交给另一台机器，接收方未必按相同顺序解释，因此协议要规定字节序。允许用字符字节复制可平凡复制对象的表示，依据是 [C++ 对象表示规则](https://eel.is/c++draft/basic.types)。

### 1.2.2.3 定点整数：原码、反码、补码与移码

以总共 8 位、包含符号位为例：

| 表示 | +5 | -5 | 8 位有符号范围 |
| --- | --- | --- | --- |
| 原码 | `00000101` | `10000101` | -127～127，有 +0 和 -0 |
| 反码 | `00000101` | `11111010` | -127～127，有 +0 和 -0 |
| 补码 | `00000101` | `11111011` | -128～127，只有一种 0 |

反码的负数由对应正数逐位取反得到；补码再加 1。对于总位数 n，原码/反码范围为 `-(2^(n-1)-1)` 到 `2^(n-1)-1`，补码范围为 `-2^(n-1)` 到 `2^(n-1)-1`。原笔记中“最小值是 2^n”漏掉了负号，也混淆了总位数与数值位数。

补码可以让加减共用加法电路，又消除了两个零。现代主流 C/C++ 实现采用补码，C++20 起有符号整数的对应表示也采用补码规则；但**有符号整数溢出仍然是未定义行为**，不能因为硬件会截断就按无符号回绕来写程序。无符号 n 位整数的范围是 `0～2^n-1`，其算术按模 `2^n` 进行。

这一区别可以直接验证，但不要运行有符号溢出来“猜规则”：

```cpp
#include <cassert>
#include <iostream>
#include <limits>

void unsigned_wrap() {
    unsigned value = std::numeric_limits<unsigned>::max();
    ++value;
    assert(value == 0);
    std::cout << value << '\n'; // 保证输出 0，不依赖 unsigned 恰好有 32 位。
}
```

假设无符号类型有 n 个值位，最大值是 `2^n-1`，加一得到的数学值是 `2^n`，对 `2^n` 取模后就是 0。把类型换成 `int` 后，这段推导就不成立：C++ 的有符号溢出规则没有给出回绕结果。这里刻意不用 `unsigned char` 演示加法，避免先发生整数提升，使“表达式在哪种类型里计算”又成为另一个问题。

这两个算术边界由 [C++ 基本整数类型规则](https://eel.is/c++draft/basic.fundamental)规定，不能仅从某次生成的机器指令推导语言保证。

移码（偏置表示）保存的是“真值 + 偏置”。只有采用特定偏置 `2^(n-1)` 时，才可由同宽补码翻转最高位得到；浮点指数常用偏置表示，但 IEEE 的偏置通常是 `2^(k-1)-1`，不能直接套用这个翻转规则。

### 1.2.2.4 定点小数与浮点数

定点数把小数点位置约定好，例如整数 1234 表示 12.34，计算时要自己维护缩放因子。加减双方需具有相同尺度；乘除还要处理尺度变化、舍入和溢出。

常见 IEEE 754 二进制浮点格式由符号位、**偏置指数**和小数字段组成，指数不是补码：

| 格式 | 符号位 | 指数位 | 小数字段位 | 指数偏置 |
| --- | --- | --- | --- | --- |
| binary32，通常对应 `float` | 1 | 8 | 23 | 127 |
| binary64，通常对应 `double` | 1 | 11 | 52 | 1023 |

对规格化数，值为 `(-1)^符号 × 1.小数字段 × 2^(指数-偏置)`，隐藏的最高有效位为 1。特殊指数要单独判断：

- 指数全 0、小数字段全 0：正零或负零。
- 指数全 0、小数字段非 0：非规格化数，隐藏位为 0，指数按 `1-偏置` 计算，用来逐渐接近零。
- 指数全 1、小数字段全 0：正无穷或负无穷。
- 指数全 1、小数字段非 0：NaN，表示“非数”。

无穷和 NaN 是两类编码，不能混写。上述格式可对照 [Oracle《Numerical Computation Guide》的 IEEE 格式说明](https://docs.oracle.com/cd/E19059-01/stud.10/819-0499/ncg_math.html)。

## 1.2.3 存储层次与介质

常用的层次是“寄存器 → CPU Cache → 主存 RAM → SSD/HDD”。越靠近执行单元，通常延迟越小、容量越小、单位容量成本越高。各层传送的单位并不相同。

### 1.2.3.1 RAM、ROM、SRAM、DRAM

RAM 是可读写的随机访问存储器，主存中的普通 RAM 是易失性的。ROM 一类存储器用来保存固件等断电后仍需保留的内容；传统掩膜 ROM 不可改写，EEPROM、Flash 等可以按各自机制擦写，不能把“ROM”一概理解为永久不能修改。

- SRAM 不需要像 DRAM 那样周期性刷新，延迟低、成本高、密度低，常用于 CPU 缓存和 TLB 等结构。
- DRAM 依靠电容存储电荷，需要刷新，密度高、单位容量成本低，常用于内存条。

功耗还与容量、工艺和工作方式有关，不能只凭 SRAM/DRAM 名称就断言总功耗谁更高。

### 1.2.3.2 磁盘的扇区、文件系统的块、虚拟内存的页

传统机械硬盘的一个记录面对应一个磁头；同一记录面有多条磁道，不同记录面相同半径的磁道组成柱面，磁道再划分为扇区。历史上的 CHS 地址用柱面/磁头/扇区定位；现代设备接口通常使用 LBA，SSD 也不能套用机械磁头结构。

扇区是设备提供的逻辑寻址/传输单位，物理扇区与逻辑扇区还可能不同。文件系统按自己的块或 extent 管理文件；操作系统按页管理虚拟内存；CPU Cache 按缓存行填充和维护一致性。一次页面 I/O 可以涉及多个扇区，文件读取也可能合并为更大的请求。

## 1.2.4 Cache 为什么有效，怎样保存数据

### 1.2.4.1 局部性与多级缓存

时间局部性是“刚用过的内容，近期可能还会用”，例如循环反复读取同一变量。空间局部性是“访问某处后，可能很快访问附近”，例如连续数组、相邻成员和顺序指令流。

CPU 利用局部性，把主存内容的一部分保存在 Cache 中。常见处理器有：

- L1：最接近核心，容量较小、延迟低，通常分为指令缓存 L1I 和数据缓存 L1D。
- L2：通常比 L1 大、延迟更高，可以每核私有，也可以由若干核心共享。
- L3：通常是更大的末级缓存，现代处理器中一般在芯片内或同一封装内，常供多个核心共享；“L3 通常在 CPU 芯片外”不是现代通用结论。

具体层数、共享关系、包含关系和容量都要看处理器。Cache Line（缓存行）是这里讨论的基本单位，常见大小为 64 B，但不是所有体系结构都固定为 64 B。

### 1.2.4.2 映射：某个内存块能放在哪里

把主存按缓存行大小编号之后，可以讨论映射方式：

| 方式 | 放置规则 | 例子与代价 |
| --- | --- | --- |
| 直接映射 | 每个主存块只能放在一个指定缓存行 | 64 个主存块、8 个缓存行时，目标行是 `主存块号 % 8`；块 0、8、16 会争同一行 |
| 全相联 | 可以放进任意缓存行 | 放置灵活，但查找标签的硬件代价较高 |
| 组相联 | 先按块号确定组，再放进该组任意一路 | 折中方案；若有 4 组、每组 2 路，则组号为 `主存块号 % 4` |

当可选位置已经占满，才需要替换策略。LRU 淘汰最近最久未用的行，LFU 倾向淘汰访问次数少的行，FIFO 淘汰最早进入的行，RAND 随机选一行。它们是策略模型；真实硬件常采用近似 LRU 等实现，不能默认精确记录所有访问时间，也不能断言随机策略永远命中率最低。

### 1.2.4.3 推演：同一份 4×4 数据，两种访问顺序

先用一维数组明确位置，再把它看成 4 行 4 列。第 `row` 行、第 `col` 列位于 `row * 4 + col`，不是四份单独分配的数组。

```cpp
#include <array>
#include <cassert>

void traversal() {
    std::array<int, 16> values{};
    for (int i = 0; i < 16; ++i) values[i] = i;

    int row_sum = 0;
    for (int row = 0; row < 4; ++row)
        for (int col = 0; col < 4; ++col)
            row_sum += values[row * 4 + col];

    int column_sum = 0;
    for (int col = 0; col < 4; ++col)
        for (int row = 0; row < 4; ++row)
            column_sum += values[row * 4 + col];

    assert(row_sum == 120 && column_sum == 120);
}
```

计算结果相同；为了看访问成本，另外建立一个**只有两行、每行容纳四个 int、初始为空的直接映射 Cache 模型**。模型中块号为 `index / 4`，缓存行号为 `块号 % 2`：

| 遍历 | 元素下标顺序 | 模型中发生什么 |
| --- | --- | --- |
| 逐行 | `0,1,2,3,4,5,6,7,...` | 每个块第一次缺失，后面三个元素命中；共 4 次缺失 |
| 逐列 | `0,4,8,12,1,5,9,13,...` | 每列按块 `0,1,2,3` 访问；0 与 2 争行 0，1 与 3 争行 1；共 16 次缺失 |

实验源码的 `CacheModel` 逐次记录这些标签并断言 `4/16`，因此这是可以核对的模型结果。它**不是实机耗时测试**：真实 CPU 的缓存容量、相联度、预取、编译优化都不同，这 16 个元素很可能很快全部留在缓存里。这个例子要学的是“访问顺序 → 块序列 → 命中/冲突”的推导方法；要比较真实程序性能，还需足够的工作集、可靠计时和目标机器上的测量。

### 1.2.4.4 写命中与写不命中要分开讨论

写命中表示目标行已在该级 Cache 中：

- **直写（write-through）**：更新本级时也向下一级发送写入，常配合写缓冲；流量较大，但下一级更及时地得到更新。
- **回写（write-back）**：先改本级并标记为脏，淘汰或一致性协议要求时再向下传递，减少写流量。

“下一级”可能仍是 Cache，并不一定是 DRAM。L1 必然直写、L2 必然回写的分法不成立，许多现代 L1 数据缓存也采用回写。

写不命中表示本级没有目标行：

- **写分配（write-allocate）**：为该行分配位置，取得所需数据和写权限后在缓存中修改，常与回写搭配。不是必须“先更新主存，再把主存调入”。
- **非写分配（no-write-allocate）**：把写请求交给更低层，本级不因此填入该行，常与直写搭配。

回写允许 DRAM 暂时不是最新值，协议负责让后续读取拿到正确数据。这与“存在未处理的数据不一致漏洞”不是同一回事。

## 1.2.5 多核之间的缓存一致性

### 1.2.5.1 MESI 的四种状态

![缓存一致性](assets/cache-coherence.png)

缓存行保存标签 Tag、数据和状态；缓存控制器负责解释请求、转移状态。协调方式可以是广播监听，也可以结合目录，不能想象成缓存行自己主动发命令。

| 状态 | 含义 |
| --- | --- |
| M，Modified | 本缓存持有修改后的独占副本，较低层可能还是旧值 |
| E，Exclusive | 本缓存独占且干净，数据与较低层一致 |
| S，Shared | 可由多个缓存共同持有的干净副本 |
| I，Invalid | 该副本无效，不能据此读取 |

### 1.2.5.2 用 X 从 0 改到 2 串起一次过程

以下是**经典 MESI 的教学流程**：两个核心 C1/C2，X 位于缓存行 L。`GetS` 表示请求可读共享副本，`GetM/Upgrade` 表示请求独占修改权限；这些是协议示意名，并非所有处理器的固定总线命令。

| 步骤 | 请求及状态变化 | 简化后的结果 |
| --- | --- | --- |
| 0. 初始 | 内存中 X=0，两个核心均无有效 L | 内存 0；C1=I，C2=I |
| 1. C1 读 X | C1 缺失，发 GetS；没有其他持有者，取回数据，获得 E | 内存 0；C1=E/0，C2=I |
| 2. C2 读 X | C2 发 GetS；C1 的 E 降为 S，C2 获得 S | 内存 0；C1=S/0，C2=S/0 |
| 3. C1 写 X=1 | C1 发 Upgrade/GetM，使 C2 的 L 失效；收到所需 ACK 后取得修改权限并写入 | 内存 0；C1=M/1，C2=I |
| 4. C2 再读 X | 最新值在 C1；C1 提供 X=1。经典 MESI 中 M 降为 S 时需要把脏数据交回一致性层次 | 简化为内存 1；C1=S/1，C2=S/1 |
| 5. C2 写 X=2 | C2 请求修改权限，C1 失效并确认，C2 转 M 后修改 | 内存 1；C1=I，C2=M/2 |
| 6. C2 淘汰 L | M 行必须写回更低层，才能丢弃最新副本 | 最终内存 2；C1=I，C2=I |

步骤 2 的干净数据可来自内存或其他缓存；步骤 4、6 的回写也可能先到下一级缓存，未必立即落到 DRAM。MOESI、MESIF 等扩展协议还有额外状态，所以用这张表理解“谁持有最新数据、谁能写”，不要把每次总线动作当成所有 CPU 的实现。

### 1.2.5.3 为什么有缓存一致性，x++ 仍然会错

普通 `x++` 包含读取、加一、写回。两个线程可能都读到 0，然后分别写回 1。缓存协议协调对缓存行的访问，不会自动把这三个动作组成一次原子读改写。对于未同步的普通 C++ 变量，这还构成数据竞争，行为未定义。

`AtomicX.fetch_add(1)` 要求一次原子读改写：其他针对该原子对象的操作不能看到被拆开的中间步骤。硬件可能通过缓存行独占、带锁指令或独占访问重试等机制实现；“锁住缓存行”只是部分实现的粗略解释，不是 C++ 标准要求，也不是每次都锁内存总线。

缓存一致性与**不同地址之间的内存顺序**还要区分。后者涉及编译器、Store Buffer、处理器内存模型及 C++ 的同步规则，见[线程与原子操作](processes-threads-and-synchronization.md)。x86 的缓存控制、原子操作和异常细节可查 [Intel 架构软件开发手册](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html)。

## 1.2.6 虚拟内存：硬件转换，操作系统管理

应用程序通常使用虚拟地址，MMU 依据页表把它转换为物理地址。虚拟地址空间提供隔离、权限控制、按需分配和共享映射；地址编号可以连续，但**合法映射并不覆盖整个空间**，页框也不要求物理连续。

一次地址转换先尝试 TLB。TLB miss 时继续查询页表；有效映射可以直接填入 TLB，只有映射不存在或权限不满足等情况才产生缺页异常。操作系统再判断是否能分配页、读取文件/交换区、处理写时复制，还是应当报告非法访问。TLB miss 不等于缺页。

### 1.2.6.1 装入与重定位的教材模型

- 绝对装入：事先确定运行地址，把相应地址写进程序；适合地址布局固定的简单系统。
- 静态重定位：装入时一次性修正地址。若之后再移动，还需要重新修正这些引用。
- 动态重定位：访问时由硬件转换地址。教材可用“基址寄存器 + 偏移”说明；现代分页通过页表和 MMU 完成，不能只归结为一个重定位寄存器。

这与链接器修正符号地址、加载器修正模块基址有关联，但不是同一层操作。

### 1.2.6.2 分页、分段与页面置换

分页把虚拟空间分为固定大小的页，把物理内存分为对应页框，通过页表映射；页通常不是程序员按业务语义划分的。分段按代码、数据等逻辑单位划分可变长区域，段表记录基址、界限和保护信息；段页式可先定位段，再在段内分页。现代主流 64 位系统通常主要依靠分页管理，具体分段功能要看体系结构。

物理页框不足时，操作系统选择可回收页。FIFO 按进入先后选择，LRU 利用近期访问历史，Clock 用访问位和循环扫描近似近期使用情况；LFU 则关注使用次数。干净文件页可以丢弃后重新读取，脏页是否写回、匿名页是否换出取决于页的来源和系统配置。

**工作集**是一个观察窗口内访问过的页面集合，**驻留集**是当前实际留在物理内存中的页面集合。如果活跃工作集长期装不进可用页框，就可能频繁换入换出，即抖动：大量时间耗在缺页处理和 I/O，吞吐量明显下降。工作集大小是配置驻留集的重要依据，不是“只要大小满足就绝不缺页”的保证。

## 1.2.7 指令的长度、操作数与寻址

### 1.2.7.1 指令长度

教材会按机器字长把指令分为半字长、单字长、双字长等。定长指令便于对齐取指和译码，变长指令可在编码密度与表达能力之间取舍；两者的扩展性还取决于编码设计，不能简单说定长一定不可扩展。变长指令集也不意味着每条指令长度都不同。

### 1.2.7.2 零至四地址指令

“地址数”是教学模型中显式操作数字段的数量，字段不一定真指向内存：

| 类型 | 一种典型含义 |
| --- | --- |
| 零地址 | 操作数隐含，例如栈机从栈顶取数；NOP、停机等无操作数指令也可没有地址字段，但不是栈运算 |
| 一地址 | 显式给出 A1，另一个操作数或结果位置隐含，例如累加器；结果去哪里由指令定义 |
| 二地址 | `A1 ← A1 OP A2`，一个字段同时作为输入和输出 |
| 三地址 | `A3 ← A1 OP A2`，两个输入和一个输出，常用于算术/逻辑描述 |
| 四地址 | 在三个操作数字段外再显式给出后继指令地址 A4，属于经典模型 |

三地址不是专门的子程序控制指令，四地址也不能直接等同于转移指令。

### 1.2.7.3 指令寻址与数据寻址

指令流可以顺序前进，也可以通过分支、调用、返回等跳转。取到指令之后，还要解释其中的操作数：

```text
立即寻址：A 本身就是数据。
直接寻址：A 给出内存地址。
寄存器寻址：A 是寄存器编号，读取寄存器中的值。
寄存器间接寻址：A 选择寄存器，寄存器内容才是内存地址。
```

立即数字段宽度影响能编码的数值范围；直接地址字段宽度影响该种编码可表达的地址范围；寄存器编号字段宽度影响可编码的寄存器数量；寄存器间接寻址的地址能力还取决于地址宽度规则。实际指令集还可能组合基址、变址、比例因子和位移。

## 1.2.8 中断与异常：怎样暂时转去执行内核代码

异常通常由当前执行引发，是同步事件，例如缺页、除零、非法指令。外部中断由设备或其他硬件事件提出，通常与正在执行的指令异步，例如定时器和 I/O 完成通知。键鼠输入可能间接产生设备中断，DMA 传输完成也可触发中断。

### 1.2.8.1 Fault、Trap、Abort

以下分类主要按 x86 教材语境理解：

- **Fault（故障类异常）**：保存的位置通常指向引发异常的指令，处理后有机会重试，如可恢复缺页。除零、非法指令也可属于 fault，但并不保证 OS 能修复后继续。
- **Trap（陷阱类异常）**：通常在相关指令完成后报告，返回位置通常是后续指令，如部分调试事件。系统调用可通过专用入口指令或软件中断实现，不能把所有系统调用都机械归为同一种 trap。
- **Abort（终止类异常）**：通常无法可靠地恢复并重试原执行，例如严重机器错误；处理方式取决于故障，可能终止进程或系统，不必一律重启。

保存的返回位置不是统一意义上的“断点”；它由异常类型和体系结构规定。

### 1.2.8.2 可屏蔽中断的响应条件

普通外部可屏蔽中断受到中断屏蔽状态、优先级和处理器可中断点约束。在 x86 中 IF 影响普通可屏蔽中断；它不等于“所有异常和中断的总开关”，同步异常与 NMI 有各自规则。NMI 也有架构规定的阻塞/嵌套限制。

教材常说“当前指令完成后响应”，这是便于建立模型的概括；具体可中断点、可重启指令等需要按架构理解，不能据此认为所有异常都要等当前指令成功执行完毕。

### 1.2.8.3 从入口到返回

“中断隐指令”是在教材中对硬件入口动作的概括，不是一条程序员可直接写出的普通指令：

1. **硬件进入入口**：保存规定的返回位置和状态，必要时切换权限级和栈，依据向量表/描述符表转去处理入口。屏蔽状态是否改变取决于入口机制。
2. **软件保护现场**：入口代码保存后续处理可能破坏、而硬件未自动保存的寄存器。
3. **处理事件**：确认中断来源、执行必要处理，较长工作可以推迟到其他上下文完成。
4. **恢复并返回**：恢复软件保存的现场，使用体系结构的异常/中断返回机制恢复控制流和相应状态。

向量通常是入口的索引或类型号，表项再给出入口描述；软件查询也可用于辨别共享中断的实际来源。中断处理并非从头到尾必然不可打断：内核可按设计允许更高优先级中断或嵌套。恢复现场也不是“由关中断指令完成”，关中断只是在特定阶段控制可被打断的范围。

## 1.2.9 把硬件路径自己走一遍

先遮住后面的解释，检查自己能否说出中间步骤：

1. `0x01020304` 放在小端机器上，最低地址处是什么？是 `04`；数值没有变成 `0x04030201`，变的是各字节的位置。
2. 上面的两种数组遍历都得到 120，为什么模型缺失次数不同？加法使用的元素集合相同，但访问块的次序不同；列遍历反复驱逐下一次还要访问的块。
3. TLB 没命中，是否必须读硬盘？不必。先查页表；映射有效时可以继续查 CPU Cache，甚至整个过程都不需要读取 DRAM。
4. 两个核心都能得到最新缓存行，普通 `x++` 是否就能安全计数？不能；缓存行一致性没有把 C++ 的读、加、写变成原子操作，未同步的普通共享访问还会产生数据竞争。

这些问题能串起来之后，再进入操作系统：硬件负责执行和保护，OS 决定哪些地址、文件和执行机会可以交给程序。
