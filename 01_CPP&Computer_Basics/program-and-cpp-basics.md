这一节是整本手册的起点。先认识变量、表达式、分支、循环、函数和对象，能跟着一次运行算出结果，再去理解 CPU、内存和操作系统。暂时不需要背虚表、完美转发或内存序。

贯穿后文的教学项目叫 **Arena**：一个小型射击练习场。这里先只模拟“玩家受到三次伤害”，不依赖游戏引擎、图形窗口或网络。第四章再把输入、移动、开火、命中和多人同步接起来。

## 1.1.1 先看完整程序，再拆开理解

下面是独立的 C++17 程序。先预测输出，再运行；暂时不懂的语法可以顺着后面的小节逐项找回来。

```cpp
#include <iostream>

int ApplyDamage(int health, int damage) {
    if (damage < 0) {
        return health; // 本例不把负伤害当治疗
    }
    if (damage >= health) {
        return 0;
    }
    return health - damage;
}

int main() {
    int health = 100;
    const int hits[] = {30, 30, 50};

    for (int damage : hits) {
        health = ApplyDamage(health, damage);
        std::cout << "health=" << health << '\n';
    }
    return 0;
}
```

预期输出：

```text
health=70
health=40
health=0
```

第三次命中时还有 40 点血，受到 50 点伤害，函数返回 0。直接写 `health -= damage` 会得到 -10；先明确业务规则，再选择代码，是后面设计武器、网络和资源管理时共同的方法。

这里假设传入血量在 `0～100`。函数不是任意整数输入的完整战斗系统；正式接口还要决定非法血量、护甲、友伤、死亡状态和重复结算怎样处理。

## 1.1.2 一份源码怎样变成一次运行

```text
编辑 .cpp 文本
→ 编译器检查名字、类型和语法，生成目标代码
→ 链接器连接当前文件和所需库
→ 得到可执行文件
→ 操作系统建立进程，运行库启动
→ 进入 main，执行程序
```

`#include <iostream>` 让当前翻译单元获得标准输入输出所需的声明；它不是运行到这一行时才把库“加载进内存”。`std::cout` 是标准输出流对象，`<<` 在这里表示把值写入流。不要和整数的按位左移混为同一用途。

在具备相应工具链的终端中，可以运行：

```sh
g++ -std=c++17 -Wall -Wextra -pedantic main.cpp -o arena_intro
```

MSVC 使用类似 `cl /std:c++17 /EHsc /W4 main.cpp` 的命令，需要先配置该工具链环境。Windows 与其他平台生成的文件格式不同，C++ 语法相同不等于可执行文件能直接跨平台复制运行。

编译与运行是两次不同的检查：

| 问题 | 常见发现阶段 | 例子 |
| --- | --- | --- |
| 语法、名字或类型不合法 | 编译 | 漏分号、拼错变量、调用不匹配的函数 |
| 有声明却没有所需定义 | 链接 | 调用了只声明、未提供实现的函数 |
| 输入不满足约定、访问失效对象 | 运行或分析 | 越界、悬空指针、数据竞争 |
| 程序能运行，但业务结果错 | 测试与推演 | 换弹扣错弹药、同一发伤害结算两次 |

编译通过只排除一部分问题。后文的[内存与编译](memory-and-compilation.md)会再拆开这些阶段，这里先建立完整路径。

## 1.1.3 变量：名字、类型、值与生命周期

```cpp
int health = 100;
const int magazineCapacity = 30;
double reloadSeconds = 1.5;
bool alive = health > 0;
```

变量声明先告诉编译器怎样解释值、允许哪些操作。`int` 适合这一小范围的整数示例，`double` 保存浮点数，`bool` 表达真/假，`const` 表示这里不能通过该变量修改其值。

声明一个局部变量不等于立刻“向操作系统申请一块堆内存”。值可能放在寄存器、栈或被优化消除。现在先关注语言里的值与使用范围，后面再看实现如何存放。

### 1.1.3.1 初始化与赋值发生在不同时间

```cpp
int ammo{30};  // 初始化：创建 ammo 时给初值
ammo = 29;    // 赋值：修改已经存在的 ammo
// int shots{2.5}; // 错误示例：花括号初始化拒绝这种窄化
```

先初始化再读取，能避免大量错误。`int count;` 在某些局部情形下没有可直接使用的初值，不要靠“调试时刚好是 0”判断正确性。

### 1.1.3.2 整数除法与浮点除法

```cpp
int whole = 5 / 2;                         // 2
double stillWhole = 5 / 2;                 // 2.0
double fraction = static_cast<double>(5) / 2; // 2.5
```

右侧先计算，再赋给左侧。第二行不会因为接收类型是 `double` 就把此前的整数除法改成浮点除法。计算命中率、动画比例和时间时，这个差别很容易造成“数值一直是 0”。

浮点值通常只能近似表示实数。时间与几何计算需要考虑误差；金额、协议字段、计数也不要随意混用浮点类型。固定宽度整数和数值表示在下一节继续讲。

## 1.1.4 表达式和分支：先把规则写完整

`=` 是赋值，`==` 是比较。`&&` 表示逻辑与，`||` 表示逻辑或，`!` 取反。逻辑与、逻辑或具有短路求值：右侧可能根本不执行。

```cpp
bool CanFire(int health, int ammo, bool reloading) {
    return health > 0 && ammo > 0 && !reloading;
}
```

逐项代入：`CanFire(100, 1, false)` 为真；死亡、空弹匣、换弹中，任意一个条件成立都不能开火。这个函数只判断条件，不扣子弹、不播放声音。把“查询”和“改变状态”分开，后面会更容易复用和测试。

### 1.1.4.1 用枚举表达互斥状态

```cpp
enum class WeaponState { Ready, Reloading, Disabled };

WeaponState state = WeaponState::Ready;
switch (state) {
case WeaponState::Ready:
    // 检查射速和弹药，再决定是否开火
    break;
case WeaponState::Reloading:
    // 处理换弹完成条件
    break;
case WeaponState::Disabled:
    break;
}
```

三个随意组合的布尔变量可能出现“既在换弹、又已禁用、同时仍 Ready”的矛盾。枚举适合描述一个维度上的互斥状态；生命状态、武器状态、网络状态仍然可以是不同维度，不能把整个角色所有状态挤成一个巨型枚举。

## 1.1.5 数组与循环：重复处理同类数据

```cpp
const int damages[] = {10, 20, 30};
int total = 0;
for (int damage : damages) {
    total += damage;
}
// total == 60
```

范围 `for` 依次取得数组元素。这里 `damage` 是每次迭代的副本，改变它不会改写原数组；需要修改原元素时，要学习后面的引用规则。

有索引的循环适合需要位置的信息：

```cpp
int hits[3] = {10, 20, 30};
for (int i = 0; i < 3; ++i) {
    hits[i] += 1;
}
// hits 为 11、21、31；合法下标是 0、1、2
```

条件写成 `i <= 3` 会访问 `hits[3]`，超出数组范围。普通数组的 `[]` 不自动做边界检查，程序可能继续运行，但行为已经不受语言保证。

`break` 结束当前循环，`continue` 跳到下一次迭代。`while` 适合次数事先未知的过程，但必须能解释退出条件；不要把“直到网络有数据”为由写一个无休止占满 CPU 的空转循环。

## 1.1.6 函数：把输入、输出与副作用分开

入门程序中的 `ApplyDamage` 按值接收两个整数并返回新血量。参数是本次调用中的局部值：

```cpp
int original = 100;
int result = ApplyDamage(original, 30);
// original 仍为 100，result 为 70
original = result;
// 明确赋值之后，original 才变成 70
```

调用者决定怎样使用返回值。这也是“计算伤害”和“把结果写回角色”可以分层的原因。后面学习引用参数和成员函数时，再比较直接修改对象的接口。

一个函数至少应说明三件事：接收什么合法输入，返回什么结果，是否改变外部状态。文件写入、发网络包、播放音效都属于需要考虑的副作用；纯计算例子更容易用确定的输入验证。

### 1.1.6.1 用 struct 把相关状态放在一起

```cpp
struct Player {
    int health{100};
    int ammo{30};
};

Player a;
Player b;
a.health = ApplyDamage(a.health, 30);
// a.health == 70，b.health == 100
```

`Player` 定义一种类型，`a` 和 `b` 是两个对象。成员名字相同，不表示共享同一份数值。类、封装、继承和多态会在后面展开；先把“类型描述规则，对象保存本次状态”记清楚。

## 1.1.7 让运行结果成为证据

对应的[入门实验](../examples/course/intro-labs.cpp)将上面的规则整理成可运行程序，并使用断言检查边界：

```cpp
#include <cassert>
// 与前面的 ApplyDamage 定义一起使用
assert(ApplyDamage(100, 30) == 70);
assert(ApplyDamage(40, 50) == 0);
assert(ApplyDamage(70, -1) == 70);
```

断言表示程序员认为此处必须成立的条件。它适合本节的小实验，但发布构建定义 `NDEBUG` 后普通 `assert` 可以被移除，不能用它替代网络包或用户输入的运行时校验。

调试时按“能稳定复现的输入 → 预期值 → 实际值 → 第一次分歧”追踪。看到最终血量不对，先找第一次计算错误，而不是直接在最后加一行补偿。

## 1.1.8 学完后应能独立回答

1. 为什么 `double ratio = 1 / 2` 得到 0？怎样改成 0.5？
2. 三次伤害为 30、30、50 时，每次调用的两个实参分别是什么？
3. 将函数调用写成 `ApplyDamage(health, 30);` 而不接返回值，外部 health 会不会变化？
4. 数组长度是 3 时，循环条件为什么是 `< 3`？
5. `Player a; Player b;` 与“两个名字指向同一个对象”有什么不同？

参考：第一题要在除法前让至少一个操作数成为浮点数；第二题依次为 `(100,30)`、`(70,30)`、`(40,50)`；第三题不会；第四题最大合法下标是 2；第五题涉及两个独立对象，别名会在指针与引用一节学习。

完成后接着看[计算机组成原理](computer-architecture.md)：同一个加法在语言层表示数值运算，在硬件层又怎样变成指令、寄存器和内存访问。
