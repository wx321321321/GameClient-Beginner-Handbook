# 杂项

## 欧拉角与四元数

### 欧拉角：
```
可以把物体想象成装在三层嵌套圆环中：
Yaw：左右转头
Pitch：抬头、低头
Roll：歪头
本质上就是依次应用三个旋转矩阵：
R = Ryaw × Rpitch × Rroll
具体乘法顺序会因内旋、外旋、坐标系和引擎约定而变化。
```
#### 问题：万向节锁
```
仍然想象三个嵌套圆环。当 Pitch 转到 90° 时，原本代表 Yaw 和 Roll 的两根旋转轴可能重合。
原来有三个独立方向：锁住以后，Yaw 和 Roll 实际在绕同一根轴旋转，于是只剩下两个独立自由度。
这并不是物体“不能转了”，而是：当前这套三个欧拉角参数无法独立描述三个方向的微小变化。
常见表现包括：某个角度突然剧烈跳变；调整 Yaw 却产生类似 Roll 的效果；动画插值经过某些姿态时突然翻转；同一姿态可以转换出多组不同欧拉角。
万向节锁不是浮点误差，而是欧拉角这种参数化方式本身存在奇异点。
```

#### 优缺点：
```
优点：
符合人的直觉，方便策划和美术调节；
三个数字即可表示；
适合限制单个方向，例如相机 Pitch 限制在 [-80°, 80°]；
方便显示在编辑器面板中。
缺点：
旋转顺序不同，结果不同；
存在万向节锁；
同一姿态可能有多组表示；
角度会在 180° 和 -180° 之间跳变；
直接对三个角做线性插值，路径通常不自然。
```

### 四元数：
```
任意一个三维旋转，都可以理解为：找到一根单位轴 n，然后绕这根轴旋转 θ。
```

#### 没有万向节锁，方便插值

#### 优缺点
```
优点：
没有欧拉角表示中的万向节锁；
旋转组合稳定；
只用四个数，比 3×3 旋转矩阵紧凑；
适合 Slerp、Nlerp 等姿态插值；
很适合骨骼动画、相机和运行时姿态计算。
缺点：
不符合人的直觉；
不能直接随意修改 x、y、z、w；
使用过程中应维持单位长度，累计计算后可能需要归一化；
q 和 -q 表示同一姿态；
乘法顺序仍然重要；
转换成欧拉角时，角度仍可能跳变。
```


### UE中使用：
#### 存储：
```
struct FTransform
{
    FQuat   Rotation;     // 旋转：四元数
    FVector Translation;  // 平移
    FVector Scale3D;      // 缩放
};
```
#### 使用：CPU端，可直接使用FTransform
