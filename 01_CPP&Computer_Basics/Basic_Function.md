# 函数

### 一个函数的基本组成：
##### 返回值类型
表示这个函数执行完会返回返回值类型。
##### 函数名
函数的名字，用来调用它
##### 参数列表
表示调用函数时，要传两个 int
##### 函数体
真正执行的逻辑

在编译阶段的语义处理中，首先通过函数名，搜索定义域。
名称重整：随后，编译会将函数名、参数重整为一个新名称，放入符号表中，供链接器区分。

## 五函数
### 普通构造函数：
如果包含基本数据类型，且自定义了构造函数，编译器不会再主动对这些值清零，默认构造函数会清零。
不能直接在一块内存上强行调用构造函数，绝对不可以是虚函数，但可以private（实现单例）。
#### A* ptr = new A(); 
底层其实发生了两件事
##### 分配内存 (Allocation)：
系统调用 operator new，在堆区强行划出一块 sizeof(A) 大小的生肉（Raw Memory），此时里面全是乱码。这步是有返回值的（返回 void* 地址）
##### 执行构造：
编译器把刚才那块生肉的地址作为隐藏的 this 指针，塞进构造函数里执行。构造函数的作用，仅仅是对这块已经存在的内存进行“精装修
内存已经分配好了，指针也已经拿到了，构造函数执行完毕后自然不需要再“返回”任何东西。
因为构造函数没有常规的函数类型，这导致了一个在 C++ 泛型编程中非常著名的限制：你永远无法获取构造函数的指针（无法取地址）。构造函数的初衷：构造函数从不“返回”对象，它只是在一块已经分配好的内存上执行初始化逻辑
#### Trivial
在 C++ 底层，如果一个类的构造、拷贝、析构等全都是由编译器默认生成的，这个类就会被标记为 Trivial
#### 初始化列表
##### 构造函数体内初始化与初始化列表的区别：
内部初始化是先用对象的默认构造函数，在用拷贝赋值函数传给对象，后者直接默认构造，
像 const 常量和 & 引用，它们在 C++ 中的规则是一旦出生就必须绑定/赋值，且终生不能修改。如果你到进入 {} 函数体再去给它们赋值，就晚了
禁用了拷贝赋值，就不能在函数体内初始化
##### 在初始化列表里写的代码顺序，编译器根本不看！编译器只看这些变量在类里面（通常是头文件里）声明的先后顺序，成员变量的构造顺序，死死绑定在它们在类中的声明顺序上。
```
花括号初始：
void Draw(vector p) {}
Draw({1, 2});
隐式转换！编译器用 {1, 2} 悄悄构造了vector
```

### POD：
#### trivial
对于 Trivial 类型，可以直接调用C 语言的 memcpy 进行内存块级拷贝，速度快。但只要你写了一个 A() {}，这个类就不再 Trivial，编译器就不敢使用 memcpy，只能老逐个调用函数，这会产生不必要的函数调用开销
##### 特点：
没有自定义的构造函数 / 析构函数。
没有虚函数（Virtual Functions）和虚继承。（一旦有了虚函数，编译器就会在内存里偷偷塞入一个虚表指针 vptr，数据就不纯粹了）。
没有自定义的拷贝/移动语义。（也就是不能重载 = 运算符）。
它的成员变量也必须都是“平凡的”。
#### Standard Layout
内存排列必须和纯 C 语言一模一样，编译器绝对不能在里面搞什么“优化重排”：
##### 特点：
所有非静态成员变量的访问权限必须完全一致（要么全是 public，要么全是 private。如果混用，编译器可能会为了安全打乱它们在内存里的先后顺序）。
没有任何引用类型的成员（Reference）。
只要有父类，数据就只能存在于继承树的同一个层级中（比如父类有成员变量，子类就绝不能再加新的成员变量）。
#### 优点：
##### memcpy 与 memset 自由（Trivial）
它是连续且没有虚函数表的“死肉”，你可以直接用极其底层的 C 函数 memcpy 把一万个 POD 结构体瞬间拷贝到另一块内存，或者用 memset 瞬间清零。如果你对一个带有虚函数或者 std::string 的类做 memcpy，内存当场爆炸
##### 与 C 语言无缝交互（standardlayout）
无论是调用操作系统的底层 API，还是与 Lua、Python 的 C-API 通信，POD 是唯一能让不同语言完美达成共识的“世界通用语”
##### 极速的网络序列化与磁盘存档
如果你要存盘或者发网络包，POD 结构体不需要写复杂的序列化代码。你可以直接把它的内存地址强转成 char*，算出 sizeof()，当成纯粹的字节流（Byte Stream）一把梭发出去。对面收到字节流后，再原封不动地强转回结构体，数据完美复原！
##### c++20:POD太过笼统，有时我们只要求是STDlayout/Trivial
    std::is_trivial<T>::value\nstd::is_standard_layout<T>::value

### 析构函数：对象离开作用域（生命周期结束）或者被 delete 时系统自动调用
#### 特点：
（1）析构函数可以（且经常需要）被手动调用
（2）可以是虚函数，也可以private（但就不能在栈上创建了，也不能delete，类内部必须提供一个公有的释放函数）。
（3）不能抛出异常：否则会使析构函数直接结束。
#### 调用delete：
##### 执行析构 (Destruction)：
编译器把隐藏的 this 指针传给 ~A()。析构函数负责“拆迁”——释放你手动申请的堆内存、关闭文件句柄，然后编译器会自动按照成员变量声明的逆序，调用内部所有成员的析构函数。
##### 释放内存 (Deallocation)：
析构逻辑执行完毕后，系统才会调用底层的 operator delete，把这块已经变成空壳的生肉（Raw Memory）还给操作系统或堆管理器。
##### 构造和赋值的区别：
前者从无到有，后者从有到无再到有，因此要进行自身的检查。
### 拷贝构造函数
##### 参数const ClassName&，无返回值
参数引用的原因：如果是传值，调用拷贝构造函数本身就需要传递参数，而传递参数又会触发拷贝构造函数…… 这会导致无限递归
### 拷贝赋值运算符
##### 参数const ClassName&，返回值ClassName&
赋值的逻辑是先释放自己的内存，然后根据对方大小申请内存并拷贝值，所以必须要if (this == &other) return *this做自赋值判断，免得先free自己再去拷贝
##### 返回引用：
为了支持连续赋值语法：a = b = c;（相当于 a.operator=(b.operator=(c))
##### 如何防止别人对一个临时对象（右值）调用赋值或修改状态的成员函数
Matrix& operator=(const Matrix& other) &;
```
本质上是在限定 this
f() &   // 只能给左值对象调用
f() &&  // 只能给右值对象调用
```
#### noexcept 
是 C++11 引入的一个关键字。当你把它加在函数声明的尾部时，你其实是在向编译器和整个程序库发誓不会报错
##### 为什么vector需要：
会出现搬4个元素，第五个空间不够的情况，然后新的和旧的都是错的，因此需要移动的函数来进行保证。同时，STL 标准库使用了一个叫做 std::move_if_noexcept，如果你的移动构造没有 noexceptvector 会认为中途可能出错。为了安全，它绝对不敢用移动操作，而是全部退化为调用拷贝构造函数
### 移动构造函数
##### 参数const ClassName&，
删除了拷贝操作后，编译器会自动禁用移动操作，但显式 delete 语义更清晰
